# Privacy

- **Error reporting and analytics** (FRK-56): None at launch. No SDK for either in the app. Crash data comes only from what Apple and Google collect from players who opt in.
- **Encryption export answer** (FRK-56): `ITSAppUsesNonExemptEncryption` is `YES` now that SQLCipher ships (FRK-41), as an industry standard algorithm not provided by the operating system. The owner files the French declaration or leaves France out of the launch countries. FRK-58 sets the flag in the iOS config. `docs/compliance.md` gives the reasons.
- **No error reporting or analytics SDK** (FRK-58): None ships, as the compliance review requires. The only network call is the update check.
- **Export compliance flag** (FRK-58): `ITSAppUsesNonExemptEncryption` is `true`, set in `ios.infoPlist`, as `docs/compliance.md` concludes now that SQLCipher ships. The owner files the French declaration or leaves France out.
- **No push** (FRK-53): `expo-notifications` is added for local notifications only. The app never requests a push token, so the privacy answers do not change. The library bundles Firebase Messaging on Android, which stays idle without a `google-services.json`. Verify with the network monitor check in FRK-74.
- **The notifications plugin is not listed in `app.json`** (FRK-53): It gets no options, so listing it would add nothing. Expo applies it anyway when the package is installed, which puts `aps-environment` in the iOS entitlements. EAS sets the value for the build, and a store build that does not use push is fine with it. Check on the first iOS build.
- **Privacy manifest union unchanged** (FRK-53): `expo-notifications` ships a manifest that declares the user defaults reason `CA92.1`, which `privacyManifests` already holds. `expo-local-authentication` and `expo-screen-capture` ship none. The `toEqual` test in `appConfig.test.ts` still holds.
- **No PIN, hash, salt or key in logs or errors** (FRK-53): The secure storage, install marker, clear everything and lock tests spy on the console, and the lock service never puts a PIN in an error. The clear everything result holds no error message.
