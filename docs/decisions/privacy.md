# Privacy

- **Error reporting and analytics** (FRK-56): None at launch. No SDK for either in the app. Crash data comes only from what Apple and Google collect from players who opt in.
- **Encryption export answer** (FRK-56): `ITSAppUsesNonExemptEncryption` is `YES` now that SQLCipher ships (FRK-41), as an industry standard algorithm not provided by the operating system. The owner files the French declaration or leaves France out of the launch countries. FRK-58 sets the flag in the iOS config. `docs/compliance.md` gives the reasons.
- **No error reporting or analytics SDK** (FRK-58): None ships, as the compliance review requires. The only network call is the update check.
- **Export compliance flag** (FRK-58): `ITSAppUsesNonExemptEncryption` is `true`, set in `ios.infoPlist`, as `docs/compliance.md` concludes now that SQLCipher ships. The owner files the French declaration or leaves France out.
- **No push** (FRK-53): `expo-notifications` is added for local notifications only. The app never requests a push token, so the privacy answers do not change. The library bundles Firebase Messaging on Android, which stays idle without a `google-services.json`. Verify with the network monitor check in FRK-74.
- **The notifications plugin is not listed in `app.json`** (FRK-53): It gets no options, so listing it would add nothing. Expo applies it anyway when the package is installed, which puts `aps-environment` in the iOS entitlements. EAS sets the value for the build, and a store build that does not use push is fine with it. Check on the first iOS build.
- **Privacy manifest union unchanged** (FRK-53): `expo-notifications` ships a manifest that declares the user defaults reason `CA92.1`, which `privacyManifests` already holds. `expo-local-authentication` and `expo-screen-capture` ship none. The `toEqual` test in `appConfig.test.ts` still holds.
- **No PIN, hash, salt or key in logs or errors** (FRK-53): The secure storage, install marker, clear everything and lock tests spy on the console, and the lock service never puts a PIN in an error. The clear everything result holds no error message.
- **Sentry error reporting is added** (FRK-83): The owner decided on 2026-11-19 that the app gets Sentry. This replaces the earlier entries that say no error reporting SDK ships. Analytics is still not added.
- **Reports are scrubbed by allowlist in the app** (FRK-83): Every message is removed, because an error message can quote a card, a name or a typed dare. The user, the request, extra data, unlisted tags and unlisted contexts are removed too. The error type, the stack, the release and the route names stay.
- **The route trail is the app's own** (FRK-83): Sentry's navigation integration is not used. `RouteTrail` records Expo Router's segments, so a dynamic part of a route stays as its placeholder and no id from an address is sent.
- **No `Sentry.wrap` on the root layout** (FRK-83): It adds touch tracking and performance spans, and neither is sent. Unhandled errors are caught without it, and render errors are reported by `CrashBoundary`.
- **Native crash reports are not scrubbed in the app** (FRK-83): A crash in native code is sent by the native SDK and never reaches `beforeSend`. It holds no app text. On Android it can hold a random install id made by the SDK. The Sentry organisation's server-side scrubbing and the "Prevent Storing of IP Addresses" setting cover these, and the privacy policy says a random number can be included.
- **No opt-out switch for crash reports yet** (FRK-83): The ticket leaves it to the owner. None is built. If the owner wants one, it is a settings switch that `initMonitoring` reads before it starts the SDK.
- **Development and preview builds skip the source map upload** (FRK-83): The Sentry build step fails a build that has no auth token. Those two profiles set `SENTRY_DISABLE_AUTO_UPLOAD`, so they build without one. A `production` build uploads and needs `SENTRY_AUTH_TOKEN` in the build service.
- **The DSN is read from `EXPO_PUBLIC_SENTRY_DSN`** (FRK-83): It is an environment variable of the build service and is in no committed file. A build without it sends nothing. Only the `production` environment needs it, so development and preview builds stay silent unless the owner sets it there too.
