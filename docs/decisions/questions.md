# Questions

- **Format on the question** (FRK-34): A question carries its own `format` and a deck can hold any mix. The content package ships one file per format, and a test checks that each file holds only its own format.
- **Discovery date format** (FRK-34): An ISO date and time string, checked by the schema. Storage can keep it as text.
- **Pick formats keep the phone or pass it** (FRK-35): `eitherOr` keeps the phone between picks and `guess` passes it, as the design decides. The engine does not model the passing: `stage` moves from `answering` to `secondPick` in both and the screen shows the handoff.
- **Answers use the player index** (FRK-35): `answer` takes a yes or no per player index, not per role, so the same action works whichever player holds the phone.
- **Where a played question is counted** (FRK-35): A question joins the history when it is revealed, so ending the round at the reveal keeps it, and a question the round ended on before the reveal is not counted.
- **Removing a revealed question** (FRK-35): `removeQuestion` does nothing once revealed, because the drinks and the discovery are already recorded. Switching a category off at the reveal leaves the revealed question in place.
- **Fallback order for questions** (FRK-35): The chosen format is tried first in each category, then the other enabled formats, as the ticket says. This differs from dares, which tries the preferred kind in every category before the other kind.
- **Knows best after only wrong guesses** (FRK-35): `knowsBest` is `'tie'` when guess questions were played and both players have the same number right, even zero. It is null only when no guess question was played.
- **Duplicate ids in the question list** (FRK-35): The engine deals the first question of an id and ignores the rest, so a repeated id cannot be dealt twice.
- **Screens read a turn view** (FRK-35): `questionTurnView` leaves the holder's first pick out and adds `pickLocked`, so a pick screen cannot show a private pick by reading state it should not. The pick appears only in the reveal.
- **Pacing is shared** (FRK-35): `round.ts` imports the pacing helpers and the player share draw from `pacing.ts`, with the dares deal baseline unchanged.
- **Format and topic choices are not kept** (FRK-60): Like level and length, they reset each visit. Only the names are remembered.
- **One shared list for the route group** (FRK-76): `useCustomQuestions` keeps its own state for each caller, so `OwnQuestionsProvider` in the `games/questions` layout calls it once and shares it. The list, the editor, the home count and setup then agree after a save or a delete, as `OwnCardsProvider` does for dares.
- **Home count** (FRK-76): The design draws a count chip on Your questions ("None yet", "3 written"), named with the title ("Your questions, 3 written"). The ticket only says "with its count", so this follows the design. `homeEntries` gains an optional `countOf` for it. The chip waits for the read, so it does not flash "None yet".
- **Format and category are chips** (FRK-76): The ticket names `SegmentedControl` for both. The design uses pressable `Chip`s because four format names and four category names do not fit across one control (the same limit as the dare editor). The design wins.
- **Save and Delete sit at the end of the form** (FRK-76): The ticket does not say. The design puts both under the fields, reached by scrolling, with no pinned footer, so the editor does not use the `Screen` footer the dare editor uses.
- **Delete confirm is the plain dialog** (FRK-76): The kit `Dialog` can show a danger confirm. The design draws the ordinary primary confirm, as the dare editor does, so the editor keeps it.
- **Remove option needs a named chip** (FRK-76): The design shows a chip that reads "Remove" and is named "Remove option 2". `Chip` had no way to give a name that differs from its label, so it gains an optional `accessibilityLabel`. No other screen changes.
- **Field errors are placed by the editor** (FRK-76): `save` lists the problems once for the whole question, without saying which field each belongs to. The editor runs the same core rule on each option to place them. A repeat that no pair of options explains is a repeat of a text already written. When both a text repeat and an option repeat are present, the option message shows first and the text message once it is fixed.
- **Would you rather list rows** (FRK-76): The design shows a would you rather row as its two options. A question that also has text shows the text first and the options under it. The options read "first, or second?" without changing the case of what the player wrote.
- **Start waits for the player's questions** (FRK-76): As the dares setup waits for the dares, Start stays off until the player's questions have been read, so a round never starts without them.
- **Player questions never enter secret match** (FRK-76): The editor offers four formats and no secret match, core has no player secret match format, and the secret match intro deals from the shipped decks alone, with a test that it ignores the player's questions.
- **Player text skips the editorial rules** (FRK-76): The rules for shipped questions (no gendered words, no alcohol words) do not apply to what a player writes, as for player dares.
- **Saving a change that removes discoveries asks first** (FRK-76): The repository deletes a question's discoveries when an edit gives it another format or fewer options. The editor runs the same rule (`changeInvalidatesDiscoveries`) against the stored question and, when it applies, asks with the kit `Dialog` ("Save this change?", Save or Keep editing) before saving. It asks whenever the rule applies, without looking up whether the question has discoveries, because that would need the discoveries store here. A reword keeps its discoveries and saves without asking.
- **A failed read of the player's questions starts the round without them** (FRK-76): If `listPlayerQuestions` rejects, the list counts as read and empty, so Start enables and the round starts with the shipped questions only. This mirrors dares.
