# Screens

- **Entry guard mechanism** (FRK-6): Protected groups on a navigator that stays mounted, plus a test over the real route files. A redirect in place of the navigator was tried and rejected: it looped on a deep link with the app open and re-read the settings on every flip.
- **Declining the entry confirmation** (FRK-6): Not stored, so the question is asked again at the next launch. The closing screen has a way back to the question.
- **A failed write when confirming** (FRK-6): The player is let in for that session and asked again at the next launch, so a storage fault does not lock them out.
- **Built-in sitemap route** (FRK-6): Turned off in `app.json`, because it sits outside the entry guard.
- **Game tiles on the hub** (FRK-7): Both tiles are surface-coloured cards. The design fills the available game's tile with the accent colour and puts small text on it, which fails the rule that text on the accent is large and bold.
- **Round setup before its ticket** (FRK-7): The available game's tile opens a stand-in round setup screen, so the hub works end to end. The real screen replaces it in FRK-11.
- **Sheet frame, skip row** (FRK-14): The design gives the skip row a 3px hard shadow and a 16px title. There is no shadow token, so the row has a plain border, and the title uses the 20px heading style, the nearest on the type scale.
- **Sheet frame, shape and spacing** (FRK-14): The design's 26, 14, 5 and 9px values use the nearest scale values: 24, 16, 4 and 12px. Its scrim is a fixed dark colour, and the build uses the background at 80%, as the end round dialog does.
- **Sheet frame, quiet control** (FRK-14): The design's 13px link text uses the 12px caption style, with a 48px touch area around it.
- **Sheet frame, last category hint** (FRK-14): The design's sheet has no hint line. The sheet shows the setup hint when one category is left on, so the lock has a visible reason as well as a spoken one.
- **Drink If has a home screen** (FRK-60): Unlike Freak or Drink it has four places to go, so the hub tile opens a home and the home opens setup. Secret match is a separate session from a round, because it needs two private passes.
- **`GameEntry` has an `entryRoute`** (FRK-60): The field was `setupRoute`. It is renamed because a tile now opens a game's home as well as its setup. No registered game is coming soon now, so the hub tests cover that state through the game list.
- **Entries switch on by a route** (FRK-60): `homeEntries` gives each entry a `route`, null while coming soon, so a later ticket changes one line.
- **Home shows the returning line** (FRK-60): Nothing records a first visit yet, so the home always shows the line for a return visit. The first visit line is not in `content` until something can choose it. Counts on Discoveries and Your questions wait for their hooks.
- **Format and topic switches share a card** (FRK-60): Each group is one `Card` with `grouped={false}`, so a screen reader reaches each switch, and rows are split by a border. Static cards are otherwise one accessible group.
- **Drink If play is a stand-in** (FRK-60): A header and one line, with a way back to setup, until the play ticket replaces it. It does not read the round.
- **Drink If play reads the turn view** (FRK-64): The screen reads `questionTurnView` and never the round's `current`, so the holder's first pick is not in anything it can reach. The pick view is given only a stage and the options, and keeps no state for a pick.
- **SegmentedControl can have no value** (FRK-64): The design's statement turns start with nobody answered and no radio checked. `value` is now `Value | undefined`, a type change only, so no other screen changes.
- **SteppingUpView takes a line, a cost line and a character** (FRK-64): The design (frame 7 notes) needs Theo's line, "A drink now costs {n}" and Theo in place of the gatekeeper, and says the ticket's list lacks them. All three are optional and default to the Freak or Drink values, so those screens are unchanged. This goes past the brief's lane, which named only `HandoffView` and `NotThisOneSheet`, because the design outranks it.
- **The handoff compares holders, as dares does** (FRK-64): A new holder always gets a pass the phone screen, including after a would you rather or guess question, where the phone may already be in their hands. A wrong guess about where the phone is would show one player the other's turn, so the screen asks every time.
- **Guess passes the phone again for a replacement** (FRK-64): The guess handoff is kept by question id. Not this one on the guesser's turn gives a new id, so the replacement's guesser gets the phone passed again after the holder has answered.
- **Press guard on the second would you rather pick** (FRK-64): A fast second tap on an option after the first pick counted as the other player's pick, so one player could answer for both. `PickView` now ignores presses for 700 ms after the second stage starts. It is a filter and not a disabled state, so the options look and announce the same as before, as the design needs. The screen keys the view by question, so each question is guarded again. Guess is not guarded, because its guesser has the phone passed to them first.
- **"I have" is the yes that drinks** (FRK-64): Never have I ever answers "I have" or "Never", and "I have" is sent as `true` exactly as a yes is, because the engine drinks on `true` in both statement formats.
- **Reveal reads the engine's drinks** (FRK-64): Who drinks, and how much, comes from `reveal.drinks`, and the wrong guess line takes its amount from the guesser's entry. The screen's own `penalty` sum is only the cost line on the card before the reveal.
- **Reveal group label** (FRK-64): The statement reveal is one group named "Sam, drinks 2. Alex, safe.", built from `resultLabel` with `drinksResult` and `safeResult`, since the design says it reads as one group. The chips keep the design's capitalised wording.
- **Theo's head is 64 dp** (FRK-64): The design draws his turn spot at 56 dp. The character component has three sizes, and the head crop at tile size is 64, so the turn line is 64 dp tall.
- **Theo is flustered in the bold categories** (FRK-64): The design says flustered on any Oral or Sex question and on stepping up to them. The screen keys that on the ids `c3` and `c4`, as the colour rules do, and lets covering his eyes during a private pick win.
- **Theo is not on the pass the phone screens yet** (FRK-64): The design marks a hero spot for him there, but `HandoffView` has no character on Freak or Drink either and the brief asked for the turn and step up screens only. Add an optional character prop to `HandoffView` when the designers want it.
- **Theo is drawn, not only a line of copy** (FRK-64): The ticket says his reaction on a step up is a line of copy until the art lands, and the design says to leave his spots out until then. The art has landed, so he is the `shy` character on the turn line and the step up screen, and his line is also a speech bubble there.
- **Summary stand-in** (FRK-64): The end of a round replaces the play screen with `/games/questions/summary`, a header, one line and a button home, until the Drink If summary replaces it. Its copy is in `copy.questionsPlay` and goes with it.
- **Nothing is stored on the play screen** (FRK-64): Discoveries stay in the round state and the summary saves them, as the ticket says. The screen does not touch storage.
