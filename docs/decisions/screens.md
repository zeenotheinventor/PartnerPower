# Screens

- **Entry guard mechanism** (FRK-6): Protected groups on a navigator that stays mounted, plus a test over the real route files. A redirect in place of the navigator was tried and rejected: it looped on a deep link with the app open and re-read the settings on every flip.
- **Declining the entry confirmation** (FRK-6): Not stored, so the question is asked again at the next launch. The closing screen has a way back to the question.
- **A failed write when confirming** (FRK-6): The player is let in for that session and asked again at the next launch, so a storage fault does not lock them out.
- **Built-in sitemap route** (FRK-6): Turned off in `app.json`, because it sits outside the entry guard.
- **Game tiles on the hub** (FRK-7): Both tiles are surface-coloured cards. The design fills the available game's tile with the accent colour and puts small text on it, which fails the rule that text on the accent is large and bold.
- **Round setup before its ticket** (FRK-7): The available game's tile opens a stand-in round setup screen, so the hub works end to end. The real screen replaces it in FRK-11.
- **Sheet frame, skip row** (FRK-14): The design gives the skip row a 3px hard shadow and a 16px title. There is no shadow token, so the row has a plain border, and the title uses the 20px heading style, the nearest on the type scale.
- **Sheet frame, shape and spacing** (FRK-14): The design's 26, 14, 5 and 9px values use the nearest scale values: 24, 16, 4 and 12px. Its scrim is a fixed dark colour, and the build uses the background at 80%, as the end round dialog does.
- **Sheet frame, quiet control** (FRK-14): The design's 13px link text uses the 12px caption style, with a 48px touch area around it.
- **Sheet frame, last category hint** (FRK-14): The design's sheet has no hint line. The sheet shows the setup hint when one category is left on, so the lock has a visible reason as well as a spoken one.
- **Favourite writes are optimistic** (FRK-55): The summary flips a favourite control at once, writes it through the repository and, on failure, puts it back and shows the message under that card. One message shows at a time and it clears when that control next changes. The design's engineering notes set this.
- **Favourites are ignored while the store loads** (FRK-55): The control does nothing until the personal store has loaded and the favourites are read, because a write to the placeholder store is lost when the real one arrives. It has no disabled look, since the design has none and the load finishes at launch, long before a round ends. A load that failed still allows writes, which last for the session.
- **The summary list stays in the scrolling Screen** (FRK-55): FRK-36 asks long lists to use a list component. The design's notes say a `Screen` that scrolls is fine for the summary, a round being short, and reserve the list component for the deck editor and My dares. The summary keeps `Screen scroll`, so this screen is not rebuilt around a list while the characters ticket edits it. An endless round is the one case that could grow it.
- **The save failed line is built in the feature** (FRK-55): The design has no error colour and no kit error line, only an accent "!" badge with foreground text. The summary draws it inline from kit tokens, with the alert role, until a TextField error line is built.
- **Surprises switch default** (FRK-49): On each time setup opens, not remembered, like the level and the length. Start passes `playableSurprises` when it is on and an empty list when it is off.
- **Which surprises the play screen shows** (FRK-49): `playableSurprises` in `features/roundPlay` lists `mystery`, `jump`, `swap` and `freePass`. A card with another type plays as a plain card until the screen can show it, so the next ticket adds `choice` and `timer` there.
- **Reveal before pass the phone** (FRK-49): The order is step up, reveal, pass the phone, card, so a role swap can say who takes the phone. A category jump's reveal replaces the step up screen. The design's order is used as drawn.
- **Mystery dare skips the step up screen** (FRK-49): A mystery dare that is still face down has its reveal in place of the step up screen, as a category jump does. The design draws the step up first, but that screen names the category the card hides and shows a cost one short of what passing costs. A product decision by the owner's delegate. It departs from the design.
- **Mystery penalty is category plus one** (FRK-49): The play screen adds one to the category's penalty for the line after the flip. This repeats the engine's pass cost. A test checks that the line and what `summarise` charges agree.
- **Card flip** (FRK-49): Reanimated, 120 ms out and 160 ms back, with the swap at the half-way point from the animation's finish callback. Reduce motion fades 80 ms out and 120 ms in. The constants are in `useCardFlip.ts`, as there are no motion tokens.
- **Screen reader focus after the flip** (FRK-49): `AccessibilityInfo.sendAccessibilityEvent` with the card text's ref and `focus`, not `setAccessibilityFocus` with `findNodeHandle` as the design names. The effect is the same and it needs no node handle.
- **Notice on the next screen** (FRK-49): The free pass confirmation is a `NoticeBox` on the first screen of the next card, a live region that iOS also announces. It is dropped when the player moves on, or when the round ends on that card.
- **Turn line is always a row** (FRK-49): `TurnView` draws the turn line in a row so the free pass marker can sit at its end. With no marker the row holds only the turn line.
- **Route tests and surprises** (FRK-49): Surprises are on by default, so route test helpers that start a plain round switch them off, and one route test plays with them on.
- **Drink If has a home screen** (FRK-60): Unlike Freak or Drink it has four places to go, so the hub tile opens a home and the home opens setup. Secret match is a separate session from a round, because it needs two private passes.
- **`GameEntry` has an `entryRoute`** (FRK-60): The field was `setupRoute`. It is renamed because a tile now opens a game's home as well as its setup. No registered game is coming soon now, so the hub tests cover that state through the game list.
- **Entries switch on by a route** (FRK-60): `homeEntries` gives each entry a `route`, null while coming soon, so a later ticket changes one line.
- **Home shows the returning line** (FRK-60): Nothing records a first visit yet, so the home always shows the line for a return visit. The first visit line is not in `content` until something can choose it. Counts on Discoveries and Your questions wait for their hooks.
- **Format and topic switches share a card** (FRK-60): Each group is one `Card` with `grouped={false}`, so a screen reader reaches each switch, and rows are split by a border. Static cards are otherwise one accessible group.
- **Drink If play is a stand-in** (FRK-60): A header and one line, with a way back to setup, until the play ticket replaces it. It does not read the round.
- **Partner's choice is one handoff stage** (FRK-50): The pass the phone screen works out who gets the phone from the surprise. Before the pick it goes to the chooser, and after it to the player with the chooser told to look away. A stage called `choice` shows `ChoiceView`. The second pass always shows, as the design says, and the first follows the `phoneChanges` rule for the chooser.
- **Shared top bar** (FRK-50): The End round control, the card count and the progress bar moved out of `TurnView` into `TurnTopBar`, so `ChoiceView` draws the same bar. The design says `ChoiceView` has the turn top bar.
- **Timer clock belongs to the card view** (FRK-50): `TurnView` records `Date.now()` when it mounts and gives it to the countdown, so the clock starts when the card shows. A reveal or pass the phone screen unmounts it, and a timer card always has a reveal, so the clock never starts early and each timer card has its own.
- **Not this one and the clock** (FRK-50): The ticket says Pass and "Not this one" stop the clock. Both end the card, so the countdown goes with it. Opening the sheet or the End round dialog and then cancelling leaves the clock running, because it is real time and a dialog is not a way to stretch a dare.
- **No haptic from a card that is gone** (FRK-50): The haptic is played from the countdown's end callback. A card that was passed, skipped or ended before zero never plays it, since unmounting clears the timeout.
- **Route test plays the new screens** (FRK-50): The route test with surprises on settles a choice with its first dare and waits out a timer card's clock on fake timers. Its deck holds a timer card for each category so that path can be dealt.
- **My dares is a list screen and an editor, in the dares route group** (FRK-54): The routes are `my-dares` (the list), `my-dares/new` and `my-dares/[id]`, so the entry guard covers them. The list is a plain scroll of cards, not a virtualised list, because 300 dares is the most it can hold and the summary already does the same for an endless round. If a device shows it janking, move it to a `SectionList` with the same padding.
- **One list of dares for the route group** (FRK-54): `OwnCardsProvider` sits in the `games/dares` layout and holds the list that the repository gives. The setup count, the list and the editor read it, so a save or a delete shows on the setup screen at once without a refresh on focus. Saving and deleting go through it, and so through the repository.
- **The category choice is four category chips, not a segmented control** (FRK-54): The design draws it that way, because the second category name does not fit a quarter of the control. The chips sit in a view with the radio group role named "Category", and each is a button with a selected state. This overrides the ticket text, which says segmented control.
- **The editor pins Save in a footer** (FRK-54): The design draws Save pinned above the keyboard, and Delete as a secondary button at the end of the form. This needs a `footer` prop on `Screen`, which the ticket does not list. It is the one file outside the ticket's list. Without the prop, Save goes at the end of the form.
- **The editor does not follow the level** (FRK-54): A new dare starts on the first category and "For your partner", whatever level setup has. The level decides which dares are dealt, as for shipped cards.
- **Save is off when the field is empty, and a field of spaces still gives the empty message** (FRK-54): Save is disabled while the field holds no characters. A field of only spaces enables it, and saving shows the empty message, because the repository tidies the text and finds it empty. Save is also off until the store has loaded, because a write to the placeholder store is lost.
- **The problem messages are mapped from core's codes in the app** (FRK-54): `cardProblemMessage` joins the message for each code, in the order core found them. `empty` stands alone and `tooLong` and `duplicate` cannot both hold, so one message shows in practice.
- **A failed write shows one line and can be retried** (FRK-54): The design has no state for a store that rejects a write. The editor shows "Couldn't save that. Try again." in the field's error line, for a save and for a delete, and the buttons work again. This is a gap in the design, not a choice made by it.
- **A dare that is not there sends the player to the list** (FRK-54): An editor link with an id that matches no dare, once the store has been read, replaces itself with the list. A dare that was deleted from the editor does not do this, because the form keeps the dare it opened with until the screen has gone back.
- **The lost data notice is held for the visit** (FRK-54): The store reports a lost key once. The list keeps showing the notice while it is open and tells the store it has been shown, so the next visit shows nothing. If the player never opens the list, the notice waits. On iOS it is announced when it shows, as the end round notice is.
- **Setup rows read as label then value** (FRK-54): The My dares row is a pressable card named "My dares, 12 written", from one line in `content`. The mix switch sits in a bordered box under it and is on each time setup opens. It shows only when there is a dare, and it applies to the starter deck only.
- **The group count is not read aloud** (FRK-54): A group heading on the list is one header element named by the category. The number of dares beside it is drawn for the eye and left out of the reading, because each dare is its own button.
- **My dares lines the design did not list** (FRK-54): `ownCards.togetherCardLabel` ("{text}, together") names a together dare's button, because the pressable card is one button and its Together chip is not read separately. `ownCards.writeFailed` ("Couldn't save that. Try again.") covers a store that rejects a write, which the design has no state for. `ownCards.backLabel` ("Back") is the back button's name on both screens. `roundSetup.myDaresRowName` ("{label}, {value}") names the setup row as label then value. `ownCards.groupHeading` ("{category}, {count}") names a group heading on the list with its count.
- **Setup waits for the dares** (FRK-54): The My dares row shows no value, and Start is held, until the dares have been read, so a round never starts without the dares it should mix. The mix switch goes back to on when the dares go from none to some.
- **A saved dare is merged into the list at once** (FRK-54): `OwnCardsProvider.save` adds the saved dare locally and then reads the list again to reconcile, so a failed read does not hide a dare that was stored. A write for a repository that a reload has replaced does not change the list.
- **Drink If play reads the turn view** (FRK-64): The screen reads `questionTurnView` and never the round's `current`, so the holder's first pick is not in anything it can reach. The pick view is given only a stage and the options, and keeps no state for a pick.
- **SegmentedControl can have no value** (FRK-64): The design's statement turns start with nobody answered and no radio checked. `value` is now `Value | undefined`, a type change only, so no other screen changes.
- **SteppingUpView takes a line, a cost line and a character** (FRK-64): The design (frame 7 notes) needs Theo's line, "A drink now costs {n}" and Theo in place of the gatekeeper, and says the ticket's list lacks them. All three are optional and default to the Freak or Drink values, so those screens are unchanged. This goes past the brief's lane, which named only `HandoffView` and `NotThisOneSheet`, because the design outranks it.
- **The handoff compares holders, as dares does** (FRK-64): A new holder always gets a pass the phone screen, including after a would you rather or guess question, where the phone may already be in their hands. A wrong guess about where the phone is would show one player the other's turn, so the screen asks every time.
- **Guess passes the phone again for a replacement** (FRK-64): The guess handoff is kept by question id. Not this one on the guesser's turn gives a new id, so the replacement's guesser gets the phone passed again after the holder has answered.
- **Press guard on the second would you rather pick** (FRK-64): A fast second tap on an option after the first pick counted as the other player's pick, so one player could answer for both. `PickView` now ignores presses for 700 ms after the second stage starts. It is a filter and not a disabled state, so the options look and announce the same as before, as the design needs. The screen keys the view by question, so each question is guarded again. Guess is not guarded, because its guesser has the phone passed to them first.
- **"I have" is the yes that drinks** (FRK-64): Never have I ever answers "I have" or "Never", and "I have" is sent as `true` exactly as a yes is, because the engine drinks on `true` in both statement formats.
- **Reveal reads the engine's drinks** (FRK-64): Who drinks, and how much, comes from `reveal.drinks`, and the wrong guess line takes its amount from the guesser's entry. The screen's own `penalty` sum is only the cost line on the card before the reveal.
- **Reveal group label** (FRK-64): The statement reveal is one group named "Sam, drinks 2. Alex, safe.", built from `resultLabel` with `drinksResult` and `safeResult`, since the design says it reads as one group. The chips keep the design's capitalised wording.
- **Theo's head is 64 dp** (FRK-64): The design draws his turn spot at 56 dp. The character component has three sizes, and the head crop at tile size is 64, so the turn line is 64 dp tall.
- **Theo is flustered in the bold categories** (FRK-64): The design says flustered on any Oral or Sex question and on stepping up to them. The screen keys that on the ids `c3` and `c4`, as the colour rules do, and lets covering his eyes during a private pick win.
- **Theo is not on the pass the phone screens yet** (FRK-64): The design marks a hero spot for him there, but `HandoffView` has no character on Freak or Drink either and the brief asked for the turn and step up screens only. Add an optional character prop to `HandoffView` when the designers want it.
- **Theo is drawn, not only a line of copy** (FRK-64): The ticket says his reaction on a step up is a line of copy until the art lands, and the design says to leave his spots out until then. The art has landed, so he is the `shy` character on the turn line and the step up screen, and his line is also a speech bubble there.
- **Summary stand-in** (FRK-64): The end of a round replaces the play screen with `/games/questions/summary`, a header, one line and a button home, until the Drink If summary replaces it. Its copy is in `copy.questionsPlay` and goes with it.
- **Nothing is stored on the play screen** (FRK-64): Discoveries stay in the round state and the summary saves them, as the ticket says. The screen does not touch storage.
- **Deck choice lives in a provider in the dares layout** (FRK-57): `DeckChoiceProvider` holds the choice so setup and the picker share it, and leaving the route group resets it to the starter deck, as the ticket asks. It is a union of `'starter'` and `'favourites'` until custom decks extend it.
- **Starter deck count in the picker is the shipped cards** (FRK-57): It leaves out the player's dares, because the mix switch belongs to setup. Setup's count line is the one that includes them.
- **The count line leaves out timer cards** (FRK-57): The design says so (FRK-39). `core` now exports `isDealable`, the rule the engine already used, so setup and the engine cannot disagree.
- **Start waits for the favourites only for Favourites** (FRK-57): The favourites are read after the screen shows, so Start and the count line wait for them when Favourites is the deck. The starter deck waits for the dares alone, so a slow read cannot hold a round that does not need it. A favourites list that cannot be read counts as empty.
- **No deck shipped now disables Start** (FRK-57): Before, Start dealt an empty deck and the round ended at once. With the in play rule, setup says there are no cards and holds Start.
- **The Favourites view reuses the summary's save failed line** (FRK-57): The design draws no failed write state for frame 16, but its notes say favourite writes are optimistic and show the error under the card. The view uses the same words, `copy.roundSummary.favouriteSaveFailed`, and the same markup. Flag for the designers if it should differ.
- **Two copy keys for a row name** (FRK-57): `roundSetup.deckRowName` repeats the pattern of `myDaresRowName`, so each row's copy stays with its own feature.
- **Settings sections and order** (FRK-63): While you play (Sounds, Vibration), Privacy (Privacy policy), Start again (Clear everything), then the version, as design frame 3 draws it without the lock, reminder and purchases rows. The sections are `SettingsSection` children, so FRK-65 and FRK-68 add their rows to Privacy by adding one child each, and the divider logic follows.
- **The hub is unchanged** (FRK-63): Frame 3 draws the hub as it is, with its secondary Settings button at the end of the list, so nothing in `features/hub` changed. The sound and vibration switches were already in Settings from FRK-26 and FRK-28, so none had to move.
- **The "What stays" list leaves out store purchases** (FRK-63): The design lists "Store purchases (Restore purchases brings them back)" and says to leave the line out if FRK-42 needs no purchase. FRK-42 is undecided and the app has no purchase code, so the line would describe nothing. FRK-71 adds it, with the Purchases section, if purchases ship.
- **The Purchases section and Restore purchases row are not built** (FRK-63): The design marks them conditional on FRK-42, and FRK-71 owns them.
- **Section captions are not headings** (FRK-63): They are plain muted text over each card, as the design draws them. Only the screen title is a heading, so the screen still has one `header` role to find. The design asks for heading levels on the privacy policy (1 for the title, 2 for sections). React Native has no heading level, so the title and each section are `header` and the order carries the structure.
- **The version comes from `expo-application`** (FRK-63): The design names `nativeApplicationVersion` and `nativeBuildVersion`, so the line matches the store. The package was already in the native fingerprint through `expo-notifications`, and `apps/mobile` now declares it directly with `expo install`. The fingerprint hash is unchanged. Under Jest the module answers "mock". Without a build number the line is `Version 1.0.0`, and without a version the line is left out.
- **The privacy screen shows the FRK-56 text** (FRK-63): Frame 5 draws placeholder words in the right shape and says the final text comes from FRK-56. The screen renders `privacyPolicy` from `content`, so its sections differ from the frame. The contact address is plain text and is not a link, since no link leaves the app.
- **Clear everything success sets no state** (FRK-63): The root remounts on success and the dialog goes with it, so the dialog stays on its clearing state until then. Only a failure sets state, which keeps the unmounted component from being updated.
- **The dialog is mounted only while open** (FRK-63): Each open asks again, and a failure does not carry over to the next open. Cancel after a failure closes it and leaves the player in Settings.
- **"Clearing" is announced** (FRK-63): The design says screen readers hear "Clearing". The confirm button's name changes to it, and the dialog also calls `announceForAccessibility`, because iOS does not read a name that changes under the focus.
- **Summary stand-in removed** (FRK-67): `SummaryStandIn` and its copy are gone. `/games/questions/summary` shows the Drink If summary.
- **Discoveries link is hidden until the screen exists** (FRK-67): The ticket allows a stand-in route or no link. A stand-in route would collide with the discoveries ticket, so `discoveriesRoute` in `features/questionsSummary` is null and the card shows the count alone, without its "See them" line. The ticket that adds the screen gives the route and the card becomes a button.
- **No card for zero discoveries** (FRK-67): A round that made none (for example only statements) shows no discoveries card and writes nothing, since "0 new discoveries" says nothing useful.
- **The guess line follows the player, not the round** (FRK-67): A player who made no guesses has no guess line, even when the other player did, because "0 of 0 guesses right" is noise. The badge still follows `knowsBest` from the engine.
- **Matches line has a singular** (FRK-67): The design has one line. A round with a single would you rather question reads "question" in the singular, as the other counts do.
- **Home does not discard the round** (FRK-67): The ticket says Home discards the round. The Drink If home is inside the same route group as the round provider, so going there keeps the round in memory until the group is left, and the next Start replaces it. Nothing is stored, so this is harmless, and a provider reset would reach outside this ticket.
- **Theo is drawn beside his line** (FRK-67): The design marks a spot for him and says to leave it out until FRK-18. The art is on main, so the summary places his head beside the line as the Drink If home does.
- **No round complete haptic** (FRK-67): The Freak or Drink summary fires one. The Drink If ticket and frame do not ask for it, so it is left out.
- **Play again rebuilds Favourites** (FRK-57): The summary reads the favourite list when Play again is pressed and builds the deck through `buildRoundDeck`, so a card unfavourited or favourited on the summary counts and the deck never goes stale. A starter deck round still replays the deck it started with, because the mix switch is not stored.
- **A favourites read does not reset on each focus** (FRK-57): `useFavouriteIds` keeps the ids it had while it reads again. Resetting them to undefined would close a gap of a few milliseconds in which Start could deal the previous favourites, but it would also blank the count chip in the picker and the count line on setup, and the cards would jump, every time a screen comes back. A press in that gap is not realistic, so the screens do not flicker.
- **A deck of timer cards only has no cards in play** (FRK-57): The count leaves out timer cards, which only the timer surprise deals, and `playableSurprises` does not include it, so such a deck shows the hint and Start is disabled. Revisit this when the timer surprise joins `playableSurprises` (the FRK-39 hand-off depends on it), because those cards then become dealable and the count and `isDealable` must follow.
