# Secret match

- **Secret match is its own reducer** (FRK-37): Secret match is a reducer in `secretMatch.ts`, not part of the round engine. It has its own state, setup and actions, and takes the questions as an argument.
- **Revealed state holds matches only** (FRK-37): The revealed state is the phase, the matches and the item count. It holds no names and no ratings, so nothing is left to leak.
- **Stop at the reveal does nothing** (FRK-37): `stop` applies in a pass and at the handoff. Once the session is revealed it returns the same state, because the reveal is the end of the session and the screens leave it by navigating.
- **Short categories in a session** (FRK-37): When a category has too few items for its share, the others make it up, mild to bold, fresh items first, then avoided ones. The session only gets shorter when the whole pool is short.
- **Player names in the view** (FRK-37): The view gives the current player's name, and the handoff view names both players, so screens hold no state to look names up.
- **Names come from the provider** (FRK-69): The rating view gives only the current player's name, but the look away line needs the other partner's. The provider keeps the two names the session started with and gives them as `players`. A name is not private, and no rating goes with it. The engine is unchanged.
- **The cover replaces the item** (FRK-69): When the app is inactive or in the background during a pass, the cover is rendered in place of the answering view, so the item and the buttons are not in the tree at all. The design drew it as an overlay. Replacing is the safer reading of the same picture, and the session is in the provider, so nothing is lost.
- **The cover is for passes only** (FRK-69): The intro, the handoff and the reveal show nothing private, so they are not covered. The handoff names both partners and the reveal shows only matches.
- **The handoff has no Stop pill** (FRK-69): Frame 11 draws only the title, the line and the button. Stop is still reachable there through the system back button and the iOS swipe, which open the same dialog.
- **Dares link follows the home entry** (FRK-69): The reveal's dares for you two card shows when the Discoveries entry of `homeEntries` has a route, and opens it. Until the Discoveries ticket gives it one, the card is hidden. No code change is needed when that ticket lands.
- **No saved line when the save fails** (FRK-69): The design has no failure line for the reveal. A failed save, and a save that has not finished, show neither "Saved to discoveries" nor the saving off line, so the reveal never claims a save that did not happen. The matches still show.
- **Design shows Theo as a spot, the app draws him** (FRK-69): The design page leaves Theo's spots empty until the characters land. The screens follow the Drink If screens: a head tile beside a line box on the intro and the reveal, a head at the end of the pass line, and the full figure on the handoff, the cover and the empty reveal. He covers his eyes in a pass, and is flustered in a bold category (`c3` and `c4`) as on the Drink If turns.
- **Matches are saved without a retry** (FRK-69): The reveal calls `addDiscoveries` once when it first shows. Opening the reveal again cannot happen, because the session is in memory and leaving the route discards it.
