# Storage

- **Personal data in a database with tables** (FRK-41): Deleting a dare has to reach its favourites and decks in one step, decks hold ordered card lists, and milestone 5 adds questions and discoveries to the same database by new migrations. Settings stay in the key-value store, which holds nothing a player writes.
- **SQLCipher build with the key in the secure store** (FRK-41): The `expo-sqlite` plugin option `useSQLCipher`, and a random 256-bit key in `expo-secure-store`, readable only while unlocked and only on this device.
- **Forward-only migrations** (FRK-41): A list of SQL steps tracked by `user_version`, one transaction per step. A database from a newer app is refused, not changed.
- **Lost key means an empty store** (FRK-41): The data cannot be read without the key, so keeping the file helps nobody. It is deleted and made again, and the repository reports it once so the screen can say so. Only SQLite's "not a database" error counts.
- **The recovery notice is not stored** (FRK-41): It lasts for the launch in which the recovery happened. A player who does not open My dares that time does not see it. Storing it would need another settings key, and the milestone 4 lock and clear everything already reset the whole store.
- **Unknown ids are kept, not pruned** (FRK-41): A shipped card can be withdrawn and come back in a later deck version, so a favourite or deck entry for a missing card is skipped on read and kept.
- **Player card and deck ids** (FRK-41): `p-` plus a UUID from `expo-crypto`, so a player id never collides with a shipped id such as `starter-c1-01`. Decks use `d-` plus a UUID.
- **Saving an id that is not stored** (FRK-41): A card or deck saved with an id that is not stored is added as a new one with a new id. It is never written under the id it was given.
- **Repeated card ids in a deck** (FRK-41): Dropped when the deck is saved, keeping the first. The core schema rejects repeats, and a screen that lists a card twice has made a slip, not a rule.
- **Transactions without `withExclusiveTransactionAsync`** (FRK-41): That call opens a second connection without the key. A transaction is run with `BEGIN IMMEDIATE` on the keyed connection behind a queue.
- **Database tests on `node:sqlite`** (FRK-41): Migrations and the repository run on the `node:sqlite` that ships with Node. Files that use it end in `.node.test.ts` and are type checked with Node's types, as the other Node-only tests are.
- **Discoveries and questions in `personal.db`** (FRK-38): Both go in a new migration step on the same database, never a second one, so deleting a question reaches its discoveries in one transaction and `clearAll` covers them with no new code.
- **Discoveries hold ids, not text** (FRK-38): A fix to a shipped question shows in old discoveries, and a discovery for a missing question is kept and comes back with it.
- **Discovery key and the empty player** (FRK-38): The key is `kind`, `question_id` and `player`. `player` is empty for `match` and `agree`, so the key needs no null, and the answerer's name for `answer`.
- **Discovery date is stored as milliseconds** (FRK-38): Like every other time in the database, and turned into the schema's ISO string on read. A row with a time that is not a date is skipped.
- **Adding over a stored key moves it to the end** (FRK-38): A replaced discovery is the newest, so a changed strength shows as recent.
- **Invalid discovery drafts are skipped, not thrown** (FRK-38): A thrown schema error can echo the values, and the engines return valid drafts. The rest of the batch is stored.
- **Positional option ids** (FRK-38): The writer types option wording only, and the repository gives `o1`, `o2` and so on. Changing a wording keeps its id and its discoveries. A change that gives a stored question another format or fewer options deletes its discoveries in the same transaction. A discovery that names an option its question does not offer is skipped on read and kept. Reordering options keeps the ids and so changes what they mean, which a screen must not offer without clearing.
- **Options need no repeat check against shipped text** (FRK-38): Options are checked for empty, length and repeats within the question. A shipped question's option wording is not a reason to refuse.
- **Question problems are one flat list** (FRK-38): The text and option problems come back together, each code once, plus `optionCount`. A screen that needs to mark the field checks the field itself. FRK-72 may ask for more.
- **Switch read from storage on each add** (FRK-38): `addDiscoveries` reads `questionPreferences` when called, so a switch turned off on the Discoveries screen is respected by a round that is already mounted. A failed read counts as the default. A switch set on the same screen wins over storage, so a failed write cannot leave saving on after the player turned it off.
- **Default for saving discoveries** (FRK-38): `defaultSaveDiscoveries` is `true` in core, built as FRK-33 recommends. The owner can flip the one constant.
- **No Face ID text in this ticket** (FRK-41): The `expo-secure-store` plugin is set with `faceIDPermission: false`, because this ticket stores a key and asks for no biometrics. FRK-53 adds the biometrics text through `expo-local-authentication`.
